- 🚨 Severity: HIGH
- 💡 Vulnerability: The CSRF token for the control plane API defaults to the exact same value as the authentication token (`CONTROL_PLANE_API_TOKEN`) if `CONTROL_PLANE_CSRF_TOKEN` is unset. This effectively defeats the purpose of CSRF protection by reusing a token intended for another purpose (AUTH-004).
- 🎯 Impact: An attacker could potentially bypass CSRF protections if they manage to compromise or leak the API token, or the system could be vulnerable to attacks assuming the tokens are distinct.
- 🔧 Fix: Implemented deterministic derivation for the fallback CSRF token by hashing the API token with a fixed secret string (`"csrf-fallback-secret"`) using `crypto.createHash("sha256")`. This ensures a distinct token is used without relying on stateful generation (like `crypto.randomBytes`), preserving horizontal scalability. Updated corresponding test mocks.
- ✅ Verification: Verified by running all tests across the `shared` and `wa-client` packages (`bun run --filter '@wbscanner/wa-client' test` and `cd packages/shared && npx jest`), confirming the CSRF token mock and derivation do not break the test suites. Checked configuration using deterministic hashing.
