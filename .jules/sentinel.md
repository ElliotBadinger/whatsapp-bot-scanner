## 2025-12-21 - SSRF Bypass via IPv4-Mapped IPv6 Addresses

**Vulnerability:** The `isPrivateIp` function failed to detect IPv4-mapped IPv6 addresses (e.g., `::ffff:127.0.0.1`) as private. This allowed SSRF bypass where an attacker could access internal services by using the IPv6 representation of private IPv4 addresses.
**Learning:** Network libraries often treat IPv4-mapped IPv6 addresses as IPv6, but they effectively route to IPv4 destinations. Simply checking IPv4 ranges against an IPv6 address object fails.
**Prevention:** Always convert IPv4-mapped IPv6 addresses to their IPv4 equivalent before checking against allow/deny lists. Use `addr.isIPv4MappedAddress()` and `addr.toIPv4Address()` provided by libraries like `ipaddr.js`.
## 2025-02-23 - Timing Attack Vulnerability in Token Comparison
**Vulnerability:** The `createAuthHook` in `services/control-plane/src/index.ts` was comparing the provided API token with the expected API token using standard string comparison `token !== expectedToken`. This simple equality check exits immediately upon finding a mismatched character, leaking timing information that an attacker could use to determine the length and value of the token over repeated guesses.
**Learning:** Standard string operators `!==` and `===` are inherently vulnerable to timing attacks when verifying secrets. Using `crypto.timingSafeEqual()` fixes this, but it must be used cautiously since it throws a 500 error if the two input buffers have different lengths (which itself leaks length information).
**Prevention:** Always convert strings to buffers (`Buffer.from(token)`) and use `crypto.timingSafeEqual()` when comparing sensitive credentials or tokens. Check the buffer lengths first; if they mismatch, perform a dummy comparison (`crypto.timingSafeEqual(expected, expected)`) before returning false to ensure the overall execution time remains relatively constant and hides the length mismatch.
